
# ОТЧЁТ ПО ИТОГАМ СПРИНТА №1

## Командный проект «Личный кабинет успеваемости студента»

**Продолжительность:** 6 учебных часов (1 день)  
**Состав команды:** 3 человека  
**Номер спринта:** 1  
**Тема спринта:** Анализ требований, пользовательские сценарии и прототип интерфейса.

---

## 1. Цель первого спринта

Целью первого спринта являлось изучение требований к мобильному приложению «Личный кабинет успеваемости студента», определение его основных возможностей, проектирование структуры приложения и создание предварительного прототипа пользовательского интерфейса.

В ходе работы команда должна была определить основные экраны приложения, разработать пользовательские сценарии, согласовать правила расчёта среднего балла и распределить обязанности между участниками.

## 2. Выполненные работы

### 2.1. Анализ требований и планирование (Product Owner / аналитик)

В начале спринта был проведён анализ требований к приложению.

Были определены основные возможности приложения:

- Просмотр общего среднего балла студента.
- Просмотр количества полученных оценок.
- Просмотр списка учебных дисциплин.
- Просмотр оценок по каждой дисциплине.
- Добавление новых оценок.
- Редактирование и удаление оценок.
- Расчёт среднего балла.
- Фильтрация оценок по периоду и типу работы.
- Просмотр динамики успеваемости.
- Расчёт необходимой оценки для достижения целевого среднего балла.

Также были определены основные пользовательские сценарии и критерии приёмки функционала.

### 2.2. Проектирование архитектуры (Lead Developer)

В ходе проектирования технической части приложения были выбраны следующие инструменты:

- Язык программирования Kotlin.
- Среда разработки Android Studio.
- Платформа Android.
- Архитектура MVVM.
- Локальная база данных Room (SQLite).
- Jetpack Compose как рассматриваемый вариант разработки интерфейса.

Была разработана предварительная структура проекта.

Определены две основные модели данных:

**Subject (Дисциплина):**
- ID дисциплины;
- название предмета;
- имя преподавателя.

**Grade (Оценка):**
- ID оценки;
- ID дисциплины;
- значение оценки;
- дата получения;
- тип учебной работы;
- комментарий.

Правила расчёта среднего балла:

Средний балл рассчитывается по формуле:

$$
S = \frac{a_1+a_2+\ldots+a_n}{n}
$$

Допустимый диапазон оценок — от 2 до 5 включительно.

### 2.3. Разработка прототипа интерфейса

Командой была подготовлена предварительная концепция пользовательского интерфейса приложения.

Для прототипирования выбрана платформа Figma.

Были определены пять основных экранов:

1. **Главный экран** — отображает общий средний балл, количество оценок и краткую информацию об успеваемости.
2. **Список дисциплин** — отображает учебные предметы, преподавателей и средний балл по каждому предмету.
3. **Экран оценок** — показывает оценки по выбранной дисциплине, даты и типы учебных работ.
4. **Экран добавления оценки** — содержит поля для ввода дисциплины, значения оценки, даты, типа работы и комментария.
5. **Экран динамики** — предназначен для отображения изменения успеваемости за выбранные периоды.

Для интерфейса выбран простой стиль оформления: светлый фон, синие кнопки, карточки дисциплин и понятная навигация.

### 2.4. Тестирование и контроль качества (QA / DevOps)

В рамках подготовки к тестированию были определены основные проверки корректности будущего приложения.

Подготовлены следующие направления тестирования:

- Проверка допустимого диапазона оценок от 2 до 5.
- Проверка правильности расчёта среднего балла.
- Проверка поведения приложения при отсутствии оценок.
- Проверка заполнения обязательных полей.
- Проверка корректности даты и типа учебной работы.
- Проверка сохранения и удаления оценок.
- Проверка отображения информации на экранах.

Также определены требования к стабильности приложения и корректности его сборки.

## 3. Пользовательские сценарии

### Сценарий 1. Просмотр успеваемости

1. Студент открывает приложение.
2. Приложение загружает сохранённые данные.
3. На главном экране отображается общий средний балл.
4. Отображается количество оценок и краткая сводка по дисциплинам.

**Результат:** студент видит общую картину своей успеваемости.

### Сценарий 2. Просмотр дисциплины

1. Студент открывает список дисциплин.
2. Выбирает необходимый предмет.
3. Приложение показывает список оценок.
4. Отображаются даты, виды работ и комментарии.

**Результат:** студент видит все оценки по выбранной дисциплине.

### Сценарий 3. Добавление оценки

1. Студент выбирает дисциплину.
2. Нажимает кнопку «Добавить оценку».
3. Вводит значение оценки.
4. Указывает дату, тип работы и комментарий.
5. Нажимает кнопку «Сохранить».
6. Приложение проверяет правильность введённых данных.

**Результат:** новая оценка сохраняется и появляется в списке.

### Сценарий 4. Редактирование и удаление оценки

1. Студент выбирает существующую оценку.
2. Нажимает кнопку «Редактировать» или «Удалить».
3. При редактировании изменяет необходимые данные.
4. При удалении подтверждает действие.
5. Приложение обновляет информацию и пересчитывает средний балл.

**Результат:** данные об оценке изменены или удалены.

### Сценарий 5. Фильтрация оценок

1. Студент открывает список оценок.
2. Выбирает нужную дисциплину.
3. Указывает период или тип учебной работы.
4. Приложение отображает подходящие оценки.

**Результат:** студент может просматривать оценки по заданным параметрам.

### Сценарий 6. Просмотр динамики

1. Студент открывает раздел «Динамика».
2. Выбирает необходимый период.
3. Приложение отображает изменение среднего балла.

**Результат:** студент может оценить изменение своей успеваемости.

### Сценарий 7. Расчёт целевой оценки

1. Студент открывает калькулятор целевого результата.
2. Вводит желаемый средний балл.
3. Приложение рассчитывает необходимую следующую оценку.
4. Если цель недостижима, выводится соответствующее сообщение.

**Результат:** студент узнаёт, какую оценку необходимо получить для достижения желаемого среднего балла.
